# Injection ground truth

**This file is the single source of truth for what gets injected, by whom, and when.**
Every other document that describes injection — `README.md`, `ARCHITECTURE.md`,
`docs/context-efficiency.md`, `docs/skills.md`, `docs/runner-surface-contract.md` — must
agree with this table. Where they disagree, this file wins and they are corrected.

Last verified against code: commit `a317a35`, agentdatabase 0.8.0.

---

## 1. The ownership rule

**AgentDB generates memory assets. AgentGate decides prevalence and injection.**

| Question | Owner |
|---|---|
| What records exist, and what is in them | **agentdb** |
| Which records a retrieval returns, and their ranking | **agentdb** |
| Which of those are *sent to the model*, and on which turn | **agentgate** (`core/injection.py`) |
| What a skill catalog contains | **agentgate** (reads operator files) |
| What the repo map contains | **agentgate** |
| Which session event opens a boundary | **agentgate** (`core/sessions.py`) |

**The test for every defect:** *is this a generation problem or a prevalence problem?* If
the record is wrong, empty, or never written — it is agentdb's. If a correct record reaches
the model at the wrong time, or is dropped when it should be sent — it is agentgate's. A
patch in agentgate to compensate for a generation defect is wrong by default, because it
hides the defect from every other consumer.

## 2. Injection objects

Every context object a turn can receive. Scope vocabulary: **boundary** = session start or
resume; **every turn** = any turn; **resume** = only a resumed session; **never** = declared
but not sent.

| Object | Generated by | Decides prevalence | Scope | Heading |
|---|---|---|---|---|
| `orientation` (workspace block) | agentgate `build_orientation` | agentgate | boundary | `## Your starting directory` |
| `orientation` (additional dirs) | agentgate `build_orientation` | agentgate | boundary | `## Additional directories available to you` |
| `repo_map` | agentgate `build_repo_map_segment` | agentgate | boundary | `## Repository map (overview; read exact source with Read/Grep)` |
| `skills_nudge` | agentgate `build_recommendation_nudge` | agentgate | every turn (Mode B only) | `## Suggested skills for this turn` |
| `skills manifest` | agentgate `build_manifest` | agentgate | session (via system prompt) | `## Available skills` |
| `memory_records` (episodic + canonical) | **agentdb** `retrieve()` | agentgate | every turn | `## Relevant memory for this turn` |
| `compaction_summary` | **agentdb** `write_compaction_summary` | agentgate | resume | `## Summary of earlier work in this session` |
| `compaction_checkpoint` | **removed in agentdb 0.8.0** | agentgate | **never** | — |
| `workspace` snapshot | **agentdb** `_build_workspace_block` | agentdb capability | boundary | `## Workspace` |
| `work_context` | **agentdb** `_build_work_context_block` | agentdb capability | every turn | `## Current work context` |

**Note on `workspace` / `work_context`:** neither is routed through `core/injection.py`
yet. They arrive inside the `prepare_turn_async` blob and agentdb supplies their headings
and their capability gates. See §6 for the gap.

## 3. Backend separation — open models vs Claude SDK

These are **different systems**, not one system with a flag. Injection must be configured
and documented per backend.

| | Open models (`deepinfra`, `fireworks`, `local`) | Claude SDK (`claude`) |
|---|---|---|
| Injection surface | `ephemeral_context` (a `system` message before the last user turn) | **none** |
| System prompt | agentgate builds it fully (`build_system_prompt`) | preset `claude_code` + `build_hard_rules()` only |
| History | agentgate's own JSON store | SDK-managed transcript |
| Resume | `build_resume_block` re-supplies the tail | native `resume=` UUID |
| Repo map | **injected** | **not injected** |
| Orientation | **injected** | **not injected** |
| Skills (manifest, tools, `//skill`) | **enabled** | **disabled entirely** |
| Tool-result compression | applies | **does not apply** |
| AgentDB capabilities | `SERVERLESS_CAPABILITIES` / `LOCAL_CAPABILITIES` | `CLAUDE_CAPABILITIES` |

**Consequence:** "inject at the session boundary" is an open-model concept. Claude has no
per-turn injection surface at all, so a parity PR cannot reuse `core/injection.py` as-is — it
needs a different seam (`enriched_prompt`, already used for its memory merge).

## 4. Platform separation — Slack vs Telegram / WhatsApp

Session identity drives this, and it is **not** cosmetic.

| | Slack | Telegram | WhatsApp |
|---|---|---|---|
| `thread_id` | `thread_ts or ts` | `str(chat_id)` | `phone` |
| Granularity | **per thread** | per chat (per user) | per phone |
| Lifetime | a thread ends, identity ends | **permanent** | **permanent** |
| New session | new thread → new identity | `/stop` then message | `/stop` then message |
| Provider cache key | new per thread | **same forever** | **same forever** |
| File attachments | downloaded to workspace | — | — |

**Consequence for injection:** on Telegram/WhatsApp a new session *mutates* the cache
lineage of a permanent address, so per-session text must never enter the cached system
prefix — it travels in the ephemeral context. On Slack the key changes per thread, so this
constraint is weaker. The current design takes the stricter path for all three, which is
correct but should be documented as a deliberate choice, not an accident.

**Consequence for configuration:** anything prevalence-related must be configurable per
backend *and* per platform, because "one turn" means very different spans across them.

## 5. Session events that trigger injection

| Event | `SessionState` | Boundary? | What is injected |
|---|---|---|---|
| First ever message | `SESSION_START` | yes | orientation, repo map, memory, workspace |
| Message after `/stop` | `SESSION_START` | yes | same — `/stop` deletes the row |
| Process restart, row survives | `SESSION_RESUME` | yes | orientation, repo map, memory, compaction summary, workspace |
| Turn after a failed turn closed the client | `SESSION_RESUME` | yes | same |
| Reaper notified idleness | `SESSION_RESUME` | yes | same, with a distinct **opener** (`⏰ Session went idle — resuming`) |
| Any later turn in an open session | `SESSION_WARM` | **no** | per-turn assets only (memory, work context, nudge) |

The idle reaper is **presentation only**. It closes the client (which is what makes the next
turn a resume) and records `idle_notified_at` to select the opener. It contributes no state
and no injection decision.

## 6. Known disconnections (as of `a317a35`)

Facts, not proposals. Each is classified by §1's test.

| # | Disconnection | Owner | Evidence |
|---|---|---|---|
| D1 | `workspace_id`, `repository_id`, `task_type`, `environment` are **never populated** | **agentdb** | 0 of 26 records; `write()` accepts them, the middleware never passes them |
| D2 | ~~`working_dirs` is empty on every record~~ **— REFUTED. Not a defect.** | none | The 4 empty episodic rows all predate the rest by hours (written before the `working_dirs` wiring landed). **Verified:** a fresh episodic record written through `prepare_turn` → `finalize_turn_async` carries `working_dirs` correctly. No action needed. |
| D3 | `min_composite_score` is **0.0** in every capability profile, so the relevance cutoff never runs | **agentdb** (default) / **agentgate** (policy) | `if min_score > 0.0:` is dead; an unrelated query returns 5 records |
| D4 | The session-topic filter **passes records that have no embedding** | **agentdb** | `if vec is None: kept.append(r)` |
| D5 | Eligibility **never excludes a record with missing identity** | **agentdb** (by design: "unknown is not a match") | deliberate, but it means unscoped records are immortal candidates |
| D6 | Consolidation is **disabled** and defaults to `since_hours=24` | **agentgate** (config) | `AGENTDB_CONSOLIDATION_ENABLED=false`; 0 canonicals exist |
| D7 | `workspace` / `work_context` are declared in `ASSET_SCOPES` but **not routed** through `core/injection.py` | **agentgate** | they arrive inside the `prepare_turn_async` blob |
| D8 | `task_type` has **no source** | **agentgate** | nothing derives it; not modelled |

**D1 is the load-bearing one.** `repository_id` and `workspace_id` are the identity
`retrieve(scope=...)` filters on, and they are never written, so a scope supplied by the
caller cannot exclude anything. Fixing that in agentgate would be a patch over an agentdb
defect.

**D2 was investigated and closed.** An earlier reading of the live store suggested
`working_dirs` was never populated, which would have blocked scoping entirely. That was
stale data: the four empty rows are the oldest in the store, written before the wiring
landed. Verified by writing a fresh record through the real middleware — it carries
`working_dirs` correctly. The remaining gap is not `working_dirs` but `repository_id` (D1).

## 7. Compression — what it touches

Three unrelated features share the word "compression". They are listed here because they
are routinely confused.

### 7.1 Tool-result compression (`core/context/tool_pipeline.py`)

| | |
|---|---|
| Flag | `AGENTGATE_TOOL_COMPRESSION_ENABLED` (**on** in the current config) |
| Applies to | **tool results only** — `role: tool` content |
| Does **not** apply to | memory, repo map, orientation, skills manifest, system prompt |
| Exempts | `skill_read` results — instructions must return exactly |
| Runs | during the tool loop, per tool call, before the result is appended |
| Backend | open models only; **Claude does not use the pipeline** |
| Session event | every tool call, every turn |
| Fallback | on any error, returns the original text unchanged |

It reduces *tool output*, not injected context. It cannot make memory irrelevant or a repo
map stale.

### 7.2 History compaction (`_maybe_compact_history`, per runner)

| | |
|---|---|
| Flag | requires `SUMMARY_MODEL_ID` — set from `{PREFIX}_SUMMARY_MODEL` |
| Current state | `DEEPINFRA_SUMMARY_MODEL` is **empty**, so compaction never runs on deepinfra |
| Applies to | the message history — old turns replaced by one summary turn |
| Side effect | fires `on_compact` → agentdb `write_compaction_summary` |
| Session event | before a request, when history exceeds 0.7 × budget |

**This is the only thing that produces a `compaction_summary` record.** With it disabled
there are no summaries to inject — which is why the record count is zero.

### 7.3 Tool-result summarisation (per runner, `_summarize_tool_result`)

Same gate (`SUMMARY_MODEL_ID`). Used when a tool result exceeds the per-result cap, as an
LLM summary instead of a hard truncation. Also off with the current config.

### 7.4 Effect matrix

| Asset | §7.1 tool compression | §7.2 history compaction | §7.3 result summarisation |
|---|---|---|---|
| `memory_records` | no | no | no |
| `compaction_summary` | no | **creates it** | no |
| `repo_map` | no | no | no |
| `orientation` | no | no | no |
| `skills manifest` | no | no | no |
| `skill_read` body | **exempt** | may evict → restoration | **exempt** |
| ordinary tool results | **yes** | may evict | **yes** |
