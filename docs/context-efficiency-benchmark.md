# Benchmark report — native context efficiency (Phase 4)

Generated by `python -m core.benchmark`. **Offline, deterministic, synthetic
fixtures.** No network or model calls were made; no provider or cached-token
numbers are claimed. These are *estimates* (~chars/3.5) on built-in fixtures, not
production measurements.

## Environment

- Repo: AgentGate working tree, branch `main`.
- Python: 3.14 (the project `.venv`).
- Commit: the commit that adds this file.
- Run: `python -m core.benchmark`.

## Variants

| Variant | What it does |
|---|---|
| A baseline | raw tool results, no transform |
| B | C1 targeted compression |
| C | C1 + C2 cross-turn dedup |
| D | C1 + C2 + C3 repo map (map adds context cost; savings are avoided re-reads) |
| E | Headroom (evaluation only, isolated; skipped if not installed) |

## Fixtures

`repetitive-log` (2,000 similar lines + one FATAL), `json-anomaly` (600 records,
one rare ERROR), `dense-asset` (40k-char low-whitespace line), `repeated-read`
(the same file read three times).

## Measured (estimated tokens per session)

| Session | A | B | C (=D here) |
|---|---|---|---|
| repetitive-log | 16,833 | 207 | 207 |
| json-anomaly | 4,948 | 227 | 227 |
| dense-asset | 11,435 | 212 | 212 |
| repeated-read | 6,513 | 321 | 273 |
| **Total** | **39,729** | **967** | **919** |

- **B vs A:** ~**97.6%** reduction on these bulky, highly-compressible fixtures.
- **C vs B:** dedup hit on `repeated-read` (321->273; 2 dedup hits on 3 reads).
- **D:** repo-map adds context tokens per session; exact source read on demand.
  With the synthetic fixtures (no repo map supplied) the delta is ~0; real repos
  add the rendered map size (bounded by `AGENTGATE_REPO_MAP_MAX_TOKENS`).
- **E Headroom:** reported **unavailable** in this environment — not claimed.

## Honesty notes (per TESTS_AND_BENCHMARKS.md)

- These fixtures are *idealized* (very repetitive). Real sessions compress less.
  A 97.6% number on synthetic logs must **not** be generalized to whole-session
  savings.
- Prefix-cache impact is **not** measured here; it requires live provider data
  with `prompt_cache_key` on vs off (the spec's H13). Treat cache economics as
  unproven until measured on real traffic.
- Task-correctness on a coding suite is **not** measured here; the unit tests
  assert FATAL lines, JSON anomalies and code identifiers survive, but a task
  suite is a separate, follow-up evaluation.
- Headroom comparison is **evaluation-only** and must run in an isolated
  environment; it is not a runtime dependency and was absent here.

## How to reproduce

```bash
python -m core.benchmark            # prints the JSON report
```

## Recommendation

- Keep every feature **off by default** (as shipped).
- The native C1/C2 path is safe and effective on tool-output-heavy sessions;
  enable per-deployment opt-in.
- Before any default-on: measure prefix-cache hit rate (H13) and task
  correctness on real sessions. Do **not** claim whole-session savings from
  these synthetic numbers.

## Prefix-cache stability (H13, offline stage)

Run: `python -c "from core.cache_stability import run_h13; print(run_h13()['all_prefixes_stable'])"`

The provider prefix cache matches the serialized request from the start. Because
every transform happens **once, at ingestion** (a new tool message is built; an
already-sent message is never rewritten), the leading messages are byte-identical
turn-over-turn for **all** variants — baseline (A), C1 (B), and C1+C2 (C). The
offline harness (`core/cache_stability.py`) confirms the reusable-prefix fraction
is **1.0** across turns for each variant, including dedup (which only shortens the
*new* duplicate message, never history).

This is the **offline, deterministic** half only. It does **not** measure provider
`cached_tokens`. A live run attaches real numbers via `record_provider_usage(report,
cached_tokens)` — same report object, no code change. Default-on still requires
that live measurement; the offline result only proves we do not *regress* the
cacheable prefix.

## Live multi-case suite (opt-in)

Run: `AGENTGATE_LIVE_TESTS=1 python -c "from core.live_task_check import run_multi_case as r; print(r())"`

Exercises four task types (log-needle, JSON-anomaly, code-identifier,
dense-line) across several **registry-validated** DeepInfra models (selection
verified with `core.reasoning.registry.lookup`; the env model runs first, then
curated flash-tier candidates). One measured run, budget 12,000 tokens:

| model | cases run | correct |
|---|---|---|
| DeepSeek-V4.1-Flash-1017 | 4 | 4 |
| MiMo-V2.6-Flash | 3 | 3 |
| Qwen3.8-Flash | 3 | 3 |

**10/10 completed cases correct:** each needle — the FATAL table name, the JSON
anomaly detail, the exact function name, the trailing dense-line token — was
recovered from the *compressed* message. Used 10,650 / 12,000 tokens; **two cases
were refused** by the guardrail because their worst-case cost (9,230) exceeded
the remaining budget — no overspend, clean skip. Every needle is independently
recoverable via `tool_result_read` (the artifact id is in the handle).

Caveat: a handful of cases on flash-tier models — evidence that compression
preserves needed content, not a full coding-task benchmark.

## Live prefix-cache reuse (H13 stage 2, opt-in)

Run: `AGENTGATE_LIVE_TESTS=1 python -c "from core.live_task_check import run_live_cache_reuse as r; print(r())"`

Two calls with an identical ~1,200-token prefix and a differing trailing
question, on `deepseek-ai/DeepSeek-V4.1-Flash-1017` (same DEEPINFRA_* env vars):

| turn | prompt_tokens | cached_tokens |
|---|---|---|
| 1 | 1214 | 0 |
| 2 | 1215 | **1152** |

The provider **reused ~95% of the stable prefix** on turn 2. With the offline
proof that native transforms never rewrite earlier messages, this shows the
features **preserve** cacheability rather than regress it. Budget: 2,434 / 8,000
tokens. Caveat: one model/endpoint; caching behavior varies by provider and
model — measure per deployment before default-on.

## Live task-correctness (opt-in)

Run: `AGENTGATE_LIVE_TESTS=1 python -c "from core.live_task_check import run_task_correctness as r; print(r())"`

Against `deepseek-ai/DeepSeek-V4.1-Flash-1017` (the runner's model, via the same DEEPINFRA_* env vars), one guarded call (~332 tokens of a 6,000 budget) produced:

- `answer_from_compressed.correct = true` — the model quoted the FATAL fact (`migration aborted, missing table 'invoices_2024'`) from the compressed tool message, so compression preserved the needed diagnostic.
- `retrieval_exact.exact_match = true` — the original is recoverable byte-for-byte via the handle.
- Budget respected: used well under the cap; the run refuses any call whose worst case would exceed the remaining budget.

This validates correctness on one case, not a full task suite. The provider reports `cached_tokens` and cost per call, which the H13 stage-2 live run can record via `record_provider_usage`.
