## 4. Findings

### 🔴 Finding 1 — BLOCKING: the isolation fixture runs too late; the leak still occurs

`tests/conftest.py` sets `PYTHON_DOTENV_DISABLED` inside a **session-scoped autouse fixture body**. However, `core.config` is imported at **collection time** (test modules do `import core.config` / `from core import config` at module top, e.g. `tests/test_runner_capabilities.py`). Collection imports happen *before* any fixture body executes, so `load_dotenv()` runs while `PYTHON_DOTENV_DISABLED` is still unset.

**Empirical proof** (clean shell — `SLACK_BOT_TOKEN`, `AGENTDB_ENABLED`, `PYTHON_DOTENV_DISABLED` all unset, so any `.env` values come only from `load_dotenv()`):

```
# Probe A — PR's session-scoped autouse fixture:
PRFIXTURE leaked SLACK=True AGENTDB=true      <-- still leaked .env into the process

# Probe B — os.environ["PYTHON_DOTENV_DISABLED"]="1" at conftest MODULE TOP LEVEL:
TOPFIX  leaked SLACK=False AGENTDB=None       <-- correctly isolated
```

So the PR's mechanism is a **no-op for the very import that causes the problem**, and the misleading docstring gives a false sense of hermeticity.

**Recommended fix:** set the variable at conftest **import time** (before any `core.config` import), not in a fixture body, e.g.:

```python
# tests/conftest.py
import os
os.environ.setdefault("PYTHON_DOTENV_DISABLED", "1")  # before pytest imports test modules
```

Alternatively set it in CI / `pytest.ini` (`env = PYTHON_DOTENV_DISABLED=1`) so it applies to collection and the worker processes. A fixture can still be kept for restoring/cleanup, but the *guard* must be set at import.

Add a regression test asserting a `.env`-only sentinel var is absent during import.

### 🟠 Finding 2 — Dependency floor is too loose (`agentdatabase>=0.1.0`)

`main` has since settled on `agentdatabase>=0.5.0` with the note: *"0.5.0 is memory-only: skill management APIs were removed from AgentDB core."* The PR pins only `>=0.1.0`, which permits older releases whose API surface differs from what the code expects. This is an availability/resolution hazard rather than a hard bug, but the floor should be tightened to the version the code actually targets (post-merge `main` already does this — **note for the record** so the merge history is understood).

### 🟡 Finding 3 — Documentation overclaims hermeticity

Once Finding 1 is fixed the docstring becomes accurate; until then, the sentence "Setting it here keeps the suite hermetic" is false and should be corrected alongside the code fix.
